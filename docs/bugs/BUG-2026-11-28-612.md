## BUG-2026-11-28-612 — "Mark Paid" on the PI detail page always failed for a foreign-currency PI `procurement` `purchase-invoices` 🟡

> **Last verified: 2026-11-28**

- **Found by:** read-only audit of 2026-11-28 (finding K2). `changeStatus` in `src/pages/procurement/PurchaseInvoiceDetail.tsx` sent `{ status: "PAID" }` only. For a USD / RMB PI the server (`src/api/routes/purchase-invoices.ts`) refuses PAID without `payFxRate` (the payment-day rate that drives the realised FX leg), so the user saw "provide payFxRate (MYR per 1 USD …)", a field the page never asked for. The list's right-click Mark Paid (`src/pages/procurement/pi.tsx`) and the phone (`markPaidBody`) both ask for the rate.
- **Fix:** the detail page asks for the payment-day rate on a non-MYR PI with the same prompt as the list (defaults to this month's Setup rate, else the booking rate) and builds the body with the shared `markPaidBody` (`src/pages/m/lib/procurement-mobile.ts`). Cancel stops; an invalid rate shows the same error as the phone. MYR PIs are unchanged.
- **Regression test:** `tests/m-procurement-mobile.test.mjs` ("Mark Paid on the PI detail page asks a foreign PI for the payment-day rate").
