# BUG-2026-11-06-429 — Fabric with stock stopped issuing to orders

**Found:** 2026-11-06, while checking the fabric usage card.

PC151-03 had 4,109 m in stock and none of its 35 October orders issued. Same for PC151-13,
PC151-17 and PC151-02.

- `consumeRawMaterialsForPO` guards each slice with `remainingQty >= qty`. The driver returns
  the float to 15 digits, so a batch left with a long fraction can read higher than stored.
  The guard then fails every time, throws "race lost", and the whole order issues nothing.
  The oldest open batch on all four fabrics carried such a fraction. Not reproduced against
  the database itself: it follows from the pattern and the guard.
- 14 fabric codes are duplicated. An unordered `LIMIT 1` could land on the empty row; PC151-01
  has 17,722 m on one row and 0 on the row added on 2026-07-02.

Fix: the guard allows 0.000001 m of slack and clamps at 0, and code lookups take the row
holding the stock.

The regression test `tests/rm-consume-guard.test.mjs` went with the revert.

## Status: reverted 2026-11-07

The fix was reverted the day after it shipped, at the owner's direction: dashboard only, WIP must not change. More issues would have moved the WIP of months with no keyed figure. Issuing stays as it was, shortages included. The fix is in git as commit 4c9d832de when the owner wants it back.
