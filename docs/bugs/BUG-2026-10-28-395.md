## BUG-2026-10-28-395: Deleted DRAFT DO kept its number on the SO, and an un-completed service order stayed READY_TO_SHIP `delivery` `production` 🟡

🟡 **On branch** (`fix/hk0118-draft-do-delete-so-stamp` → `main`). Found 2026-10-28 (HK-0118, Siti).

**Symptom.** SV-2610-036 (RX HOMICE, 4 x SERVICE CHARGE) showed Delivery Order `DO-2610-110` and READY TO SHIP, with every production line PENDING / Not started. Measured on prod 2026-10-28 (read-only): the 4 POs completed 2026-10-27 07:21 UTC and the SO went READY_TO_SHIP; Siti raised DRAFT DO-2610-110 at 07:21:54 and deleted it at 08:40; every job card was set back to WAITING at 08:47-08:48 and the POs recomputed to PENDING. `sales_orders.hookka_delivery_order` still read `DO-2610-110`, no `delivery_orders` row carried that number, and the SO stayed READY_TO_SHIP. The same stale stamp sits on SO-2610-079 (`DO-2610-105`, deleted).

**Root cause.** (1) DO create stamps `sales_orders.hookkaDeliveryOrder`; `DELETE /api/delivery-orders/:id` deleted the DRAFT DO and its items but never handed the stamp back (only the packing-list-first rollback did). (2) `cascadeUpholsteryToSO` / `cascadeUpholsteryToCO` returned early when no sibling PO had an UPHOLSTERY card, so an all-accessory / service order never reached the READY_TO_SHIP → IN_PRODUCTION rollback branch (C28 row 5).

**Fix.** DELETE /:id runs `SO_DO_STAMP_HANDBACK_SQL` in the same batch: the SO takes its newest remaining non-cancelled DO number, or blank, only while it still carries the deleted DO's number. The two cascades skip only when the order is not READY_TO_SHIP, so the forward half stays with `cascadePoCompletionToSO` and the rollback now runs for orders with no UPHOLSTERY card. SV-2610-036 is repaired by `scripts/fix-hk0118-sv-2610-036.mjs` (dry run by default; `--execute` writes): DO number blanked, status back to IN_PRODUCTION with a `so_status_changes` row. Its fg_units / fg_batches stay; the completion cascade reuses them when the POs complete again.

**Regression.** `tests/hk0118-draft-do-delete-so-stamp.test.mjs` (handback SQL on SQLite + route pin); `tests/so-ready-accessory-gate.test.mjs` "HK-0118: ..." (SO + CO rollback with no UPHOLSTERY card).
