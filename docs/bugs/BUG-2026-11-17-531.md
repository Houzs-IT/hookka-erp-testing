## BUG-2026-11-17-531 — The Board Report pre-build never built a report; a forced build died with "Worker exceeded resource limits" `board-report` `cron` 🟡

🟡 Background build shipped in #1435; renewal-on-open on branch `fix/board-report-refresh-on-open`.

**Symptom.** The owner asked (17 Nov) for the report to rebuild itself on the 1st, 7th, 10th and 15th. The first forced
run (Actions run 44096707871, 17 Nov 13:50 UTC) got HTTP 503 after 2 min 15 s with a 16-byte non-JSON body
(Cloudflare's "error code: 1102"). Every earlier daily run (8 checked) answered `built:false, note:"already kept"` —
the endpoint had never once built a report; the reports in the cache were built by people pressing Refresh.

**Cause.** `POST /api/internal/board-report-prebuild` awaited the whole build inside the request. The page's
`GET /api/reports/board?rebuild=1` builds the same report under `waitUntil` and answers within 25 s; that path works
(October rebuilt from the page at 11:10 UTC the same day).

**Fix.** The pre-build now builds under `waitUntil` like the page (200 if done within `BUILD_WAIT_MS`, else 202), and
takes `{check:true}` to report the kept copy's `generatedAt`. The workflow polls that every 20 s for up to 6 min and
passes only when the kept copy is newer than the run's start.

**Follow-up, same day.** After #1435 deployed, two forced runs (44103601581, 44104322925) got 202, then polled 18 times
over 6 min with the kept copy unchanged (generatedAt stayed 11:14:35Z) — the background build started from a GitHub
request never lands either, while Refresh from a browser does. So the owner's 1st / 7th / 10th / 15th renewal moved
into `GET /api/reports/board`: the first open of the last closed month whose kept copy was built before 00:00 MYT of
the latest of those days rebuilds it like Refresh (`boardKeptIsStale`); a poll never triggers it, so a failed build
cannot loop. The workflow no longer forces builds and a timeout is a warning.

**Regression test.** `tests/board-report-schedule.test.mjs`.
