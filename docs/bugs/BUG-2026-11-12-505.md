## BUG-2026-11-12-505 — "Reload for new version?" dialog interrupted work after every deploy `layout` `deploy` 🟢

🟡 **On branch** (`fix/hk-0146-no-reload-popup` → `main`).

**Symptom.** Hub ticket HK-0146 (Violet, 11 Nov 2026): "can help to turn off pop up notification window. too annoying during working". Her screenshot shows the dashboard's modal dialog titled "Reload for new version?" with the text "A new version is available. Reload now? Unsaved changes may be lost." and the buttons Cancel / Reload.

**Cause.** `NewVersionWatcher` (`src/layouts/DashboardLayout.tsx`) showed a toast and then, 1.5 s later, this blocking confirm every time a new deploy was detected, and main deploys many times a day. Since BUG-2026-09-23-184, `useAutoUpdateOnNavigate` already reloads on the next page change, so the dialog only offered a reload that happens anyway.

**Fix.** The dialog is gone. The toast stays ("A new version is available — it will load on your next page change."), and the reload still happens on the next page change. The phone shell (`/m`) has always worked this way. This replaces the BUG-2026-09-23-184 note that `DashboardLayout` "keeps the immediate 'Reload now' offer".

**Regression.** `tests/deploy-auto-update.test.mjs` — the dashboard shows the toast and no longer uses the confirm dialog.
