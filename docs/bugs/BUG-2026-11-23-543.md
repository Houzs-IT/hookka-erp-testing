## BUG-2026-11-23-543 — phone Scan Sales Order: Retry never re-reads a PO that came back empty `sales-orders` `scan-po` 🟡

- **Symptom:** on the phone (Home → Scan to Create → Sales Order), a real customer PO shows "Couldn't read this document. No purchase order was found in this file." Tapping Retry shows the same message at once (YH, chat, 2026-11-23, screenshot from an iPhone user).
- **Cause:** the message shows when the read finished but returned no PO with item lines (`posOfRow` in `src/pages/m/lib/scan-so.ts`). The queue stores that read as `done`, and the upload's file-hash cache in `src/api/routes/scan-queue.ts` reuses any `done` read of the same bytes. So every Retry, and every later scan of the same file by anyone in the org, got the empty result back with no new read.
- **Fix:** `src/api/lib/scan-reuse.ts` `isReusableRead` — a PO read is reused only if one PO has item lines; both cache lookups (upload and auto-split child) use it. The phone message now says when a PO was found but its item lines were not.
- **Not fixed here:** why the model returned no lines for this file. That needs the file itself.
- **Regression test:** `tests/scan-reuse-empty-po.test.mjs`.
