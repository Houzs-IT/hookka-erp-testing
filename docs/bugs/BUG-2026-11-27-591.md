## BUG-2026-11-27-591 — New Invoice dialog listed LOADED delivery orders the server refuses `invoices` `delivery-orders` 🟡

> **Last verified: 2026-11-27**

- **Found by:** reading the invoice code while writing the AI Connector how-to guides (`docs/WORK-TRACKER.md`, "AI Connector process help").
- **Symptom:** Invoices → New Invoice listed DELIVERED **and LOADED** DOs ("DELIVERED or LOADED status required"). Picking a LOADED one always answered 400 "Only DELIVERED delivery orders can be invoiced", and the dialog swallowed the error (nothing happened).
- **Which rule is right: DELIVERED.** `src/api/routes/invoices.ts` header ("Invoice creation still requires a DELIVERED deliveryOrderId"); revenue and FIFO COGS are booked on delivery (the DELIVERED cascade `buildDoDeliveredSoAndInvoice` auto-creates the invoice); a LOADED DO is still undelivered exposure in the credit check (`customer-credit.ts`); the DO list's "Transfer to Invoice" is disabled unless DELIVERED. The dialog was the odd one out, so the server rule stays.
- **Fix:** one shared rule, `src/lib/invoiceable-do.ts` (`isInvoiceableDo`, `INVOICEABLE_DO_STATUS`): the dialog lists only DELIVERED DOs not held for paperwork (delivered-with-issues, which the server also refuses), and POST /api/invoices checks the same constant. The dialog now shows the server's refusal instead of swallowing it.
