## BUG-2026-11-26-562 — Working Hours: a removed row came back after refresh `working-hours` `attendance` `payroll` 🟡

> **Last verified: 2026-11-26**

- **Report:** Hub HK-0178 (Management, 2026-11-26): a worker came in for a few minutes and punched out; Remove made the row disappear, but it came back after refresh.
- **Symptom (read on prod, read-only):** 8 workers punched 2026-11-26 from about 07:50 to 08:20 with no `working_hour_entries` row. The punch auto-fill writes nothing when the payable hours come to 0 (`src/api/lib/punch-autofill.ts` `totalHours <= 0`), so these rows on the grid are drafts with no `id`.
- **Cause:** `WorkingHoursTab.refresh` (`src/pages/employees.tsx`) adds a draft row for every punch (`attendance_records` with a clock time) that has no entry. Remove deleted only the entry (`DELETE FROM working_hour_entries`), or, for a draft with no `id`, nothing on the server at all. The punch stayed, so refresh built the row again.
- **Fix:** removing the LAST entry of a worker-day also deletes its punch and its AUTO short-hour dock, in one batch (`src/api/lib/remove-worker-day.ts`, `DELETE /api/working-hour-entries/:id`). A draft row with a punch now calls the new `DELETE /api/working-hour-entries/punch?workerId=&date=`. A split day keeps its punch until its last entry goes; a MANUAL dock is never touched. In a month with approved / paid payslips the server refuses (409) — withdraw approval first (YH, 2026-11-26: delete the punch, the selfie with it, and undo the dock; the approved-month refusal is the default picked by the fix, not yet confirmed by the owner).
- **Side effect to know:** a worker-day with no entry and no punch is an absence for payroll (`settle-period`), so removing a day moves it from a short-hour dock to an absent day.
- **Regression test:** `tests/working-hours-remove-punch.test.mjs`.
