## BUG-2026-10-22-381 — Experimental dashboard took 2-3 s to load whenever its cache had gone cold `dashboard` `performance` 🟡

🟡 **On branch** (`perf/dashboard-feed-snapshot-main` → `main`), ported from staging #1096. Found 2026-10-22 by measuring `/dashboard-experimental` on staging after the owner asked why the new dashboard loads slowly. Prod impact UNMEASURED (no prod read).

**Symptom.** Measured on staging 2026-10-22. `GET /api/dashboard/prototype` (5 MB, 306 KB on the wire) answered in 150-350 ms when warm, but **2,764 ms** after 7 minutes with no visitor, and the request right after it still took 1,906 ms. `GET /api/dashboard/overview` for a month nobody had opened took ~2.3 s against 80-175 ms warm.

**Cause.** Both feeds had only the 60 s KV copy (`cached()`, `src/api/lib/kv-cache.ts`), which is gone 6 minutes after the last read. The prototype feed had no database snapshot, and the overview's snapshot only covers `period=all`, which the new dashboard never sends (`widgetPeriod` always gives a month, quarter or year). So the first visitor after a quiet spell paid the full rebuild.

**Fix.** Both feeds read through `withSnapshot` (`src/api/lib/snapshot.ts`) behind the KV copy, into a new `dashboard_feed_snapshot` table (runtime self-applied, migration 0217). The saved copy is reused until a source table changes, served stale while it refreshes in the background, and the KV key is cleared when the refresh lands. Keys carry the payload version and the day; rows older than two days are pruned on each rebuild. A prototype payload with a failed section (`availability.*.live === false`) is not saved (new `shouldStore` option). On `main` the prototype feed also carries today's live open-punch hours, which step every 30 minutes, so its copy uses `maxAgeMs` to count as stale once a new half hour begins. On `main` every month, quarter and year uses the snapshot (no frozen months here); `period=all` keeps its own. The first visitor of each day still waits once.

**After (staging, #1096).** Prototype after a cold KV: 862-1,136 ms (was 2,764). Overview: 281-395 ms (was ~2,300). Not re-measured on `main` or prod.

**Regression.** `tests/snapshot-swr.test.mjs` (`shouldStore` false is never written, true is).

**Follow-up (2026-10-22).** The main deploy of #1097 failed in `npm test`: the change moved `dashboard-overview.ts` lines, and four module-guide anchors (`docs/modules/dashboard.md`, `docs/modules/reports.md`) drifted past the 8-line window of `tests/docs-module-guide-anchors.test.mjs`. Production kept the old build. Fixed on `fix/dashboard-guide-anchors`. Run that test before any PR that adds lines to a file the module guides anchor into.
