## BUG-2026-11-10-489 — scan-queue jsonb values were stored as JSON strings, not arrays / objects `scan-queue` `sql` 🟢

`src/api/routes/scan-queue.ts` bound `JSON.stringify(nextIdxs)` to `consumed_doc_idxs = ?::jsonb` and `JSON.stringify(result.data)` to a bare `raw_json = ?` through postgres.js `unsafe`, which encodes the string a second time: the column held a jsonb STRING, so SQL `->` read NULL. The reader (`hydrateRow`) accepts both shapes, which hid it. Sister: Houzs#5457 (H3 B5). Not checked against the live DB (UNMEASURED how many rows are string-shaped).

Fix: every jsonb write binds text and casts `?::text::jsonb`; the cache-hit copies go through `jsonbText()`, which also turns an old string-shaped value into an object. Existing rows are not rewritten; readers still accept both.

Regression: `tests/pass2-reliability.test.mjs` (B5 block).
