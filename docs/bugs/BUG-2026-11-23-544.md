## BUG-2026-11-23-544 — clicking a notification left it unread and opened the wrong page `notifications` `announcements` 🟡

- **Symptom (HK-0170, Violet, 2026-11-21):** on `/notifications`, clicking an "Acknowledged: …" row opened the Announcements form, and the bell / sidebar count stayed at 1. Order notices jumped straight to Production with no way to read the full text first.
- **Cause:** the `/notifications` row `onClick` only navigated to `link`; it never marked the row read (the bell popover did). The worker-ack alert (HK-0154) stored a hardcoded `link: "/announcements"`. The bell, pop-up and OS notification all navigated straight to `link`.
- **Fix:** a row click on `/notifications` marks it read and expands its full message, with a link button at the bottom ("Open Production Overview"). The bell, pop-up and OS notification open `/notifications?open=<id>`. New ack alerts link to the notice's order (`ackAlertLink` over `order_no` / `order_id`); a plain notice still links to Announcements. Rows already stored keep their old link.
- **Regression test:** `tests/notification-bell.test.mjs`, `tests/order-notification.test.mjs`.
