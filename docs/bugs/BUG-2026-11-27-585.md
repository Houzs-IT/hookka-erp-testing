## BUG-2026-11-27-585 — Meeting attachments opened with the uploader's file type (HTML could run as the ERP) `meetings` `security` 🔴

> **Last verified: 2026-11-27**

- **Report:** Weekly ERP R&D report 2026-11-27, finding #3 (found in Carres; same code here).
- **Cause:** `GET /api/meetings/meetings/:id/files/:fid` (`src/api/routes/meetings.ts`) passed the hub's stored type through, and `fetchBlobUrl` (`src/pages/meetings/kit-api.ts`) re-typed the blob with the uploader's `mime_type` and opened it as a same-origin blob: URL.
- **Fix:** only png, jpeg and pdf keep their type; everything else is `application/octet-stream` + `attachment` on the server, and an octet-stream blob in the page.
- **Regression test:** `tests/meetings.test.mjs`.
