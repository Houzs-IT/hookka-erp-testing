## BUG-2026-11-17-510 — A role changed on User Management didn't reach the menu / page gates; Admin saw "No access" for labour cost `auth` `rbac` 🟡

🟡 **On branch** (`fix/me-permissions-follow-gate-role` → `main`).

**Symptom.** Owner, 17 Nov 2026: Lim was set to Admin (User Management shows "Admin", the top bar says Admin), logged out and in, yet the Employees dashboard (desktop and phone) still showed "No access" for Labour and Avg labour cost / person.

**Root cause.** Two sources for a user's role. User Management's save writes `users.role` (`src/api/routes/users.ts`), and the API gate reads that (auth-middleware stamps `u.role`). But `GET /api/auth/me/permissions` — which the pages use to decide what to show — resolved `users.roleId → roles.name` FIRST, falling back to `users.role` only when the join was null. Lim's `roleId` still named his old role, so the page got the old role's permissions (no `payroll:read`) and never asked for the salary data the API would have served. Its table lookup also went by `roleId`, unlike the gate's lookup by role name.

**Fix.** `/me/permissions` takes `users.role` first (roles.name only as the fallback) and looks table-defined roles up by name, exactly as the gate does (`src/api/routes/auth.ts`). No permission is granted that the API did not already grant — the page now matches the API.

**Regression.** `tests/me-permissions-role-source.test.mjs`.
