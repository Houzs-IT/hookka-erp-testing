## BUG-2026-10-28-397: Editing an order whose POs already made finished goods failed half-saved `sales` `production` 🟢

🟢 **On branch** (`fix/hk0118-so-edit-fg-batches` → `main`). Reported 2026-10-28 by Siti (office, HK-0118 follow-up): on SV-2610-036 she put the price in and Save Changes showed "Something went wrong. Please try again."

**Symptom.** Edit page Save on an IN_PRODUCTION order returns a generic error toast.

**Cause.** Measured on prod 2026-10-28, read-only: SV-2610-036's 4 POs completed 2026-10-27, which wrote 4 `fg_units` (PACKED) and 4 `fg_batches`; the job cards were later set back to WAITING (BUG-2026-10-28-395). The PUT's edit gate checks job cards only, so the edit passed. The PUT writes the items, then the Option D rebuild deletes fg_units, job_cards and production_orders and re-creates them. `fg_batches.production_order_id` is an FK to production_orders with NO ACTION, and the rebuild does not delete fg_batches (they are FG cost lots), so the rebuild batch failed with a raw FK error. The UI humanised it to the generic line. The item write had already committed: the order reads RM 400.00, `updated_at` 2026-10-28 03:11 UTC; the PUT audit row is written after the rebuild, so there is none.

**Fix.** Before any write, the PUT looks for an `fg_batches` row under the order's POs. If there is one: an edit that changes nothing production is built from (product, category, size code, fabric, qty, inches, specials, notes, repair scope, line count; customer, state, reference, customer PO, SO date) keeps the POs and skips the rebuild; delivery-date changes re-date POs and job cards in place as for a header-only edit. An edit that does change those is refused with a 409 in plain words, before anything is written. Orders with no fg_batches behave as before. Comparison: `src/api/lib/so-production-fields.ts`.

**Not fixed here.** Un-completing job cards still leaves fg_units PACKED and fg_batches (and their cost) in place; whether un-complete should reverse finished-goods output is a separate decision.

**Checked.** Unit tests; tsc clean. SV-2610-036 needs no data change: the price is saved and its POs and job cards are untouched (4 POs PENDING, 12 job cards WAITING).

**Regression.** `tests/so-edit-fg-batches.test.mjs`.
