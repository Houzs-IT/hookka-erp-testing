## BUG-2026-11-09-431 — Capex & financing table: the popup body scrolled a few pixels beside the table (two scrollbars) `finance` `ui` ✅

✅ **Shipped (#1214) and verified on production 2026-11-09**, read only, viewport emulated: at 1236×661 the body overflows by 0 px and the table scrolls inside it (333 px tall, the month heading sticks); at 1236×480 the body overflows by 0 px (table 170 px tall); Cancel left the stored amounts empty.

**Symptom.** Found in my own read-only check on production right after #1213 shipped (2026-11-09), at the owner's screen size (1236×661, emulated): the table scrolled inside the popup as intended, and the popup body around it overflowed by 5 px, so it showed a second vertical scrollbar.

**Root cause.** #1213 capped the table's height with a guess, `max-h-[calc(90vh-16rem)]`, standing for "the popup minus its header, actions, note and padding". At that size the real chrome was a few pixels more than 16rem, and the note's height changes with the window width, so no fixed number fits every size.

**Fix.** No guessed height. `DocDetailModal` gains `fill`: the body becomes a flex column whose blocks can shrink (`min-h-0`), so the table card takes exactly the room left and its own scroller (`min-h-0 overflow-auto`) is the only thing that scrolls. Without `fill` the body is exactly as before. Checked on production before the change by trying the same rule on the open popup (inspection only): no body overflow at 480, 661 and 1000 px high; the month heading still sticks; at 1000 px the whole table shows and the popup shrinks to it.

**Regression.** `tests/finance-v2-popup.test.mjs` pins the `fill` body; `tests/cashflow-forecast-ui.test.mjs` pins that the table uses it and carries no `max-h-[calc(` guess.
