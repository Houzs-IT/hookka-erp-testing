## BUG-2026-11-23-546 — worker scans never deducted raw materials; whole PO deducted at first Fab Cut `production` `inventory` `mrp` 🟢

- **Symptom:** the owner's rule is that each WIP's materials leave stock when that WIP completes (「完成了就扣 每个wip完成的就扣」). In practice the first FAB_CUT job card completed through the PATCH path deducted the WHOLE production order's BOM (fibre, wood, everything) at once. Job cards completed by worker SCAN (`/scan-complete`, fan-out, dept scan, the sibling loop) deducted nothing at all, so stock only moved at the PO-completion safety net, often weeks later. The MRP could not be built on top of this: it would not know which materials were still to come.
- **Cause:** RM consumption was keyed on the PO (`consumeRawMaterialsForPO`, idempotent on any RM_ISSUE row for the PO) and wired only into the PATCH handler's `departmentCode === "FAB_CUT"` branch. The four scan completion sites posted labour but never called it.
- **Fix:** the shared calculation is `computeRequiredLines`, also used by the new MRP. Each job-card completion, PATCH and every scan path, calls `consumeRawMaterialsForJobCard` and deducts only the lines owned by that card's top-level WIP in that card's department. Idempotency is per `(po_id, wip_key, dept_code)` in `rm_consume_marks`, claimed before any FIFO write. POs already deducted under the old rule (RM_ISSUE but no marks) are never touched again. `consumeRawMaterialsForPO` now deducts only slices not yet deducted (the PO-completion safety net).
- **Regression test:** `tests/mrp-plan.test.mjs`.
