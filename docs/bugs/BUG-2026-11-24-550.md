## BUG-2026-11-24-550 — Purchase Invoices detail export left UOM blank on every line `procurement` `export` 🟡

- **Symptom:** Purchase Invoices > Export (the per-line detail listing, `purchase-invoices-detail-*.xlsx`) had a UOM column, but it was empty on every row. Reported by a user on 2026-11-24.
- **Cause:** `buildPiDetailListingAoa` (`src/lib/doc-detail-listings.ts`) passed a hard-coded `uom: ""`. The data was already there: `GET /api/purchase-invoices/:id` returns each line's `uom` (set only when billed in a different unit, HK-0149) and `poUnit` (the PO line's unit, from `attachPoPrices`).
- **Fix:** UOM = billed unit (`uom`) → PO line unit (`poUnit`) → the raw material's `baseUOM` (`materialUnit`, attached by `attachMaterialUnits` in `GET /api/purchase-invoices/:id`). The first two alone filled only 612 of 1,875 lines on a canary export (2026-11-24): most PIs have no PO behind them.
- **Not affected:** the "Export CSV" button exports one row per PI with no line columns, so it has no UOM.
- **Still blank:** a line whose item code matches no raw material (or matches several with different units).
- **Import:** UOM is not an editable PI import column, so a re-imported export does not write the unit back.
- **Regression tests:** `tests/doc-detail-listings.test.mjs` (UOM fallback order), `tests/pi-po-price.test.mjs` (`attachMaterialUnits`), `tests/doc-import-pi.test.mjs` (round trip stays clean with a unit exported).
