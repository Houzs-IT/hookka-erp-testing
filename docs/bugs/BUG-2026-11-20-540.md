## BUG-2026-11-20-540 — Pillows waited for the Packing scan before they could go on a Delivery Order `delivery` `production` 🟡
> **Last verified: 2026-11-20** against `src/lib/delivery-pipeline.ts` (`isPillow`, `cardsBeforePackingDone`), `src/api/routes/production-orders/_helpers.ts` (`siblingUphGateDone`, `cascadeUpholsteryToSO` / `ToCO`, `cascadeUpholsteryRollbackToSO`) and `tests/so-ready-accessory-gate.test.mjs` (branch `fix/pillow-ready-before-packing-main`, to `main`).

🟡 **On branch** (`fix/pillow-ready-before-packing-main` → `main`). Same logic as staging #1505 + #1512, checked on the staging site (9 of 9 cases). Prod effect UNMEASURED.

**Symptom.** Fibre scanned a pillow complete, but it did not show in Pending Delivery until the Packing department also scanned it. While it was being made it showed in neither Planning nor Pending Delivery.

**Root cause.** The Delivery readiness rule uses the UPHOLSTERY cards as the "made" signal. A pillow has none, so the no-Upholstery branch fell back to the PO's own `COMPLETED` status, and the PO only completes when its last card, PACKING, is done. The SO / CO READY_TO_SHIP gate (`siblingUphGateDone`) had the same fallback, and `cascadeUpholsteryToSO` / `ToCO` loaded only UPHOLSTERY cards.

**Fix.** Pillows only (owner request): `isPillow` (product code or name contains PILLOW; there is no pillow category, pillows are ACCESSORY next to cushions and service charges). A pillow is ready for a DO once every card before PACKING is done (`cardsBeforePackingDone`; an empty set never counts), shows in Planning while one is open, and counts toward READY_TO_SHIP at the same point. Used by `poReadyForDelivery`, `poReadyForConsignment`, `poInPlanning`, `poInPlanningConsignment` and the backend `siblingUphGateDone`. Every other no-UPHOLSTERY product (cushion, service charge, scoped repair) keeps the old rule. Sofas and bedframes keep the UPHOLSTERY gate and the sofa-set check. The two cascades and the SO rollback now load every card except PACKING; HK-0118's rollback for an order with no such card is kept. `PipelinePO` gained `productCode` / `productName`, passed by the dashboard pipeline (`dashboard-prototype.ts`) and the DO QR candidate check (`public-do-qr.ts`).

**Known gap, not fixed here.** Finished-goods units, the Floor rack default and the cost cascade still run when the PO completes, which is at PACKING. A DO dispatched before PACKING marks no units LOADED, and the units made later read as in the warehouse. Sofas already behave this way.

**Known limit.** A product named with PILLOW that is not a pillow takes the pillow rule; a pillow named without the word does not.

**Prod check.** UNMEASURED. On deploy, open pillow POs whose cards before PACKING are all done move into Pending Delivery, and their SOs can move to READY_TO_SHIP on the next card scan.

**Class.** C28 row 4 closed, row 6 added.

**Regression.** `tests/delivery-pipeline.test.mjs` (`isPillow`; pillow ready with PACKING pending; pillow on FIBRE not ready; cushion still waits; sofa gated on UPHOLSTERY only; CO mirror; Planning), `tests/so-ready-accessory-gate.test.mjs` (sofa + pillow SO goes READY_TO_SHIP at FIBRE done; pillow-only SO up and back down; cushion does not count before COMPLETED; DEV-08 and HK-0118 cases kept), `tests/repair-scope.test.mjs` source guard.
