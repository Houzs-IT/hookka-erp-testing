## BUG-2026-11-17-523 — Order notice in the ERP bell opened the whole production list, not the order sent `production` `notifications` 🟡

🟡 **On branch** (`claude/hk0155-notify-detail-3e6904` → `main`). Hub HK-0155, Violet, 2026-11-17.

**Symptom.** An ERP user who got a "Send Notification" order notice tapped it under Updates on
ERP mobile and landed on Production Orders with every order (986), not the one order sent.

**Cause.** `notifyErpUsers` (`src/api/routes/announcements.ts`) stored every order notice's bell
row with `link = "/production"`, and `toMobilePath` (`src/pages/m/lib/notification-links.ts`)
maps that to the `/m/production` list.

**Fix.** The row's link names the orders (`orderNoticeLink`, `src/lib/order-notification.ts`):
one order → `/production?soId=<order no>&po=<id>`; orders of one SO → `/production?soId=<SO>-`;
otherwise `/production`. Desktop opens the Overview filtered to it (the HK-0144 `?soId=` filter);
`/m` turns `?po=` into `/m/production/<id>`, the order's stage screen with Done / Pending per
department. Rows written before the fix keep the old link.

**Not fixed here.** ERP users get no phone pop-up: Web Push exists only for worker-portal
devices (`src/api/routes/push.ts`).

**Test.** `tests/order-notification.test.mjs` ("HK-0155 link", and the ERP-users-only POST
checks the stored link); `tests/mobile-updates.test.mjs` ("HK-0155").
