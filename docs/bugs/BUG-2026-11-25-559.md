## BUG-2026-11-25-559 — AI Connector leak check answered "Unauthorized" for every endpoint `ai-connector` 🟡

> **Last verified: 2026-11-25**

- **Symptom:** the first live run of the Super Admin leak check (account "sales", role SALES, approved for the run and removed straight after) returned 304 / 304 rows as `error: Unauthorized` — nothing was actually checked.
- **Cause:** the check sent each tool call back through `POST /api/mcp` (the door) with a token issued moments earlier in the same request, and the door's `resolveAccessToken` refused it on prod. The exact reason was not pinned down from outside (no prod logs read); the path had never run live before.
- **Fix:** the check no longer goes through the door. `runToolAs` (routes/mcp.ts) runs each tool in the admin's request with the staff member's role / org on the context for that call (restored afterwards) and seeds the identity with `rememberVerified`, so the module gate, redaction and the inner GET all run as the staff member. Calls run one at a time because they share the context. Permissions are looked up by the staff member's own id and role (rbac `getEffectivePermissions`), never the admin's.
- **Regression test:** none automated for the live path; verified by re-running the leak check on prod after deploy (see the PR).
