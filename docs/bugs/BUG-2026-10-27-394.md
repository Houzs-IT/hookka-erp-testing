## BUG-2026-10-27-394: Fab Sew sticker for a Sandback piece printed no component badge `production` `stickers` 🟡

🟡 **On branch** (`fix/hk0116-sandback-sticker` → `main`). Found 2026-10-27 (HK-0116, Violet).

**Symptom.** Violet's SB02 Fab Sew sticker (SO-2610-252-05) printed WIP `A01 COVE-13` and an ARMREST badge. Measured on prod 2026-10-27 (read-only): SB02's BOM is `SANDBACK` / `{MODEL} -Sandback` today, but the five SB02 POs opened 12-14 Oct (SO-2610-194-08/09/10, SO-2610-252-04/05) were exploded from an earlier BOM typed `SOFA_ARMREST` with code `A01 {FABRIC}` (A01 is the armrest product), and job cards keep the BOM they were born with. POs opened from 19 Oct carry `SANDBACK` / `SB02 -Sandback`, and their sticker printed no badge at all: `componentBadgeLabel` knew only the six built-in pieces.

**Root cause.** The sticker badge mapped only HB / Divan / Base / Armrest / Cushion / Leg; an extra WIP type added in Maintenance (Sandback, 2026-10-08) fell through to "no badge".

**Fix.** `componentBadgeLabel` moved to `src/lib/wip-types.ts` and takes the saved extra WIP type names (`variants-config.wipTypes`, Sandback by default); a job card typed with an extra type prints that type's name. The five stale POs are a data repair, separate from this change.

**Regression.** `tests/wip-types.test.mjs`: "sticker badge: extra types print their own name; built-ins and wholes unchanged".
