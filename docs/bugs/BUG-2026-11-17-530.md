## BUG-2026-11-17-530 — Any login could read the Board Report's kept copy (payroll, profit) through /api/kv-config `security` `finance` 🟡

🟡 **On branch** (`fix/kv-config-finance-keys-gated` → `main`).

**Symptom.** The owner, 17 Nov: 「全部员工都可以看到的」 → restrict the Board Report. The page and
`GET /api/reports/board` are gated on `accounting:read` (checked on prod 17 Nov, read-only: 10 of 20 active
accounts hold it — 8 Super Admins, Lim (Admin), Finance). But the built report is kept in kv_config
`board_report_cache:<YYYY-MM>`, and `GET /api/kv-config/:key` returned any key to any login with no
permission check. A Sales or QA login could read the whole October report — payroll by department, net
profit, cash — at `/api/kv-config/board_report_cache:2026-10`. The same route exposed the Forecast P&L
(`forecast_pnl`), the Cash Flow forecast inputs (`cashflow_forecast_*`) and the P&L opening balances
(`pnl_*`).

**Cause.** kv-config was built for shared settings (holidays, letterhead, variants) that every page reads,
so its GET is open. Finance features later stored their figures in the same table.

**Fix.** `src/api/routes/kv-config.ts` `GATED_KEYS`: `board_report_*` and `pnl_*` need `accounting:read`,
`forecast_pnl` and `cashflow_forecast_*` need `forecasts:read` — the same permission as the page that shows
them. Every other key keeps its open read (the front end reads only settings keys through this route;
the finance figures are read server-side). Writes already need `users:update`.

**Not changed.** Who holds `accounting:read` — the owner decides that per role (Settings › Roles).

**Regression test.** `tests/kv-config-finance-keys-gated.test.mjs`.
