## BUG-2026-10-29-399: Send Notification button invisible until orders were ticked; "already sent today" used the UTC date `production` `announcements` 🟡

🟡 **On branch** (`fix/send-notification-visible` → `main`). Reported 2026-10-19 by Violet (HK-0025): "could not see the Send Notification button". She is SUPER_ADMIN on prod, so permission was not the cause.

**Symptom.** On Production Overview the only Send Notification button sat inside the yellow "N selected" bar, which renders only when `selectedOverviewOrders.length > 0` (`src/pages/production/index.tsx`). With nothing ticked there was no sign the feature existed.

**Cause.** The entry point was tied to the selection bar. Separately, the duplicate check in `POST /api/announcements` compared `created_at` to `new Date().toISOString().slice(0,10)` (the UTC date), so 07:00 and 09:00 MYT on one day fell on different "days", and 23:30 MYT blocked the next morning's send.

**Fix.** A "Send Notification" button in the Production Tracking header on the Overview tab for users with `announcements:create`, disabled with the tooltip "Tick one or more orders first" until orders are ticked, opening the same `SendOrderNotificationDialog`; the yellow-bar button stays. The dedupe cutoff is now `mytDayStartIso()` (`src/lib/order-notification.ts`), the start of the Malaysia day.

**Not fixed here.** The PRODUCTION role's `announcements:create` grant is unchanged.

**Checked.** Unit tests; tsc clean. Header button not clicked in a browser.

**Regression.** `tests/order-notification.test.mjs` (MYT day boundary, 23:30 vs 07:00 MYT).
