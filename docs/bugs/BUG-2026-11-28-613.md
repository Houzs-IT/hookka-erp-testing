## BUG-2026-11-28-613 — Invoice server accepted a bare "PAID" status with no payment `sales` `invoices` 🟡

> **Last verified: 2026-11-28**

- **Found by:** read-only audit of 2026-11-28 (finding K3). `PUT /api/invoices/:id { status: "PAID" }` on a SENT / OVERDUE / PARTIAL_PAID invoice was an allowed transition (`INV_VALID_TRANSITIONS`, `src/api/routes/invoices.ts`). It set the status but left `paidAmount` alone, wrote no `invoice_payments` row and no ledger entry, and did not reduce the customer balance, yet the invoice left the receivables / aging lists (they filter on status). No desktop button sends it; the phone's generic bulk "Mark Paid" for invoices (`bulkMarkConfig` in `src/pages/m/screens/ModuleListScreen.tsx`) was dead only because `/m/invoices` uses its own list. Live data was clean (every PAID invoice has `paidAmount = totalSen`).
- **Fix:** after the payment-delta block the PUT refuses (409) a move to PAID while `paidAmount` (after any `paidAmount` in the same body) is below `totalSen`, and a move to PARTIAL_PAID with no payment. Sending `paidAmount` still derives the status as before, and Payments are untouched. The dead `invoices` entry in `bulkMarkConfig` is removed.
- **Regression test:** `tests/invoice-bare-paid-refused.test.mjs` (real handler: bare PAID refused from SENT / OVERDUE / PARTIAL_PAID with nothing written; bare PARTIAL_PAID refused; SENT → OVERDUE still works; no invoice bulk Mark Paid on the phone).
