## BUG-2026-11-13-510 — Mail Center stopped receiving @hookka.com mail on 2026-10-16 `mail-center` `inbound` 🔴

🟡 **On branch** (`fix/hk0150-restore-mail-sync` → `main`). Hub ticket HK-0150 (reporter Siti).

**Symptom.** Siti: mail Sim (Houzs) sent to siti@hookka.com never showed in Mail Center. Owner
measured on prod (13 Nov): the last real inbound row is 2026-10-15 09:22Z (finance@); the
2026-10-16 06:09Z row is an admin test-inject. Sim sent three mails to siti@ on 12 Nov
(Houzs prod), none reached Hookka.

**Cause.**
1. Commit `3f240466e` (T-012 R13, merged with PR 898 on 2026-10-16, no review) deleted the
   Hostinger IMAP poller (`mail-sync/`) on the premise "MX is on Cloudflare since 2026-08-19".
   It was not: hookka.com MX is mx1/mx2.hostinger.com (nslookup, 13 Nov), Cloudflare Email
   Routing on the hookka.com zone is Disabled with 0 rules, and `hookka-mail-inbound` is not
   deployed (Cloudflare dashboard, 13 Nov). Last poller run: 2026-10-16 01:42Z.
2. siti@ was never read even before that: a box with no `HOSTINGER_PW_<NAME>` secret was
   skipped with a log line, and only SUPPORT / FINANCE / HR secrets exist (`gh secret list`).

**Fix.** Restore `mail-sync/` and `.github/workflows/mail-sync.yml` from `3f240466e^` (the R12
mailbox-visibility half of that commit stays). Add the `HOSTINGER_PW_SITI` env line. A box
listed with no password now fails the run (red) instead of being skipped; the other boxes are
still synced. Comments in `src/api/routes/mail-center.ts` and the R13 line in
`docs/WORK-TRACKER.md` no longer say Cloudflare is the inbound path.

**Owner steps (not code):** set the `HOSTINGER_PW_*` secrets and the `MAIL_MAILBOXES` variable,
add the Mailbox Access rows, then run the workflow once with `since_days = 35` to catch up.
Until `MAIL_MAILBOXES` lists only boxes with a secret, every run is red (the default list
includes lim@ and violet@, which have no secret).

**Regression test.** `tests/mail-sync-missing-password.test.mjs` runs `sync.mjs` against stub
IMAP packages: a box with no password exits 1 with "no password in HOSTINGER_PW_SITI" while the
next box is still tried. Fails on the old skip code, passes now.
