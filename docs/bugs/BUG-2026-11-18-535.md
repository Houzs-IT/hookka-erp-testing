## BUG-2026-11-18-535 — ERP users got no pop-up for a new notification, only a bell row `layout` `notifications` 🟡

🟡 **On branch** (`fix/hk0155-erp-notification-popup`). Ticket HK-0155 (first half; the second half was PR #1421).

**Symptom.** "it doesn't pop up the notification. only show got message in notification." A new
notice (e.g. an order's department update) landed in the top-bar bell, but nothing appeared on screen.

**Cause.** ERP users have no Web Push (only workers subscribe, `src/api/routes/push.ts`), and the bell
(`src/components/layout/notification-bell.tsx`) fetched only on first paint, on open and on window focus,
so a user who stayed on one page never saw a new row arrive.

**Fix.** The bell polls `GET /api/notifications` every 60 s, also in a background tab (the poll is
ETag-cached, `src/api/lib/poll-etag.ts`). Unread rows not seen in an earlier load pop a clickable card
under the bell for 10 s; when the tab is hidden and the user allowed notifications, each (up to 3) also
shows as an OS notification. Either opens the same link the bell row opens and marks it read. The first
load pops nothing, a failed load changes nothing, and seen ids only grow, so the backlog never floods in
and no row pops twice. The browser permission prompt is asked on the first bell click.

**Limit.** Nothing pops while no ERP tab is open; that needs Web Push for ERP users (a follow-up).

**Test.** `tests/notification-bell.test.mjs`: first load pops nothing, only unseen unread rows pop
newest-first, seen ids only grow, and the pop-up target matches the bell row's.
