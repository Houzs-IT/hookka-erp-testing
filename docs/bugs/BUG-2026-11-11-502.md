## BUG-2026-11-11-502 — Dashboard daily "Production revenue" still priced pieces by the piece number `dashboard` `production` 🟡

🟡 **On branch** (`fix/daily-revenue-source-line` → `main`).

**Symptom.** Found 2026-11-11 by a code-reading cross-check of every production revenue figure (no database query). BUG-2026-11-11-498 moved six price lookups to the real order line, but the Dashboard › Operations daily panel ("Production revenue", per day) still joined `sales_order_items.line_no = production_orders.line_no`. For an order whose earlier line has quantity > 1, later pieces were priced from the wrong sales line, or from the product list price, so that panel disagreed with the other production revenue screens for the same day.

**Cause.** The panel's query lives inline in `src/api/routes/dashboard-prototype.ts` in snake_case SQL, so the camelCase search used for BUG-498 did not find it, and its guard test listed only the six camelCase files.

**Fix.** Both joins use `PRODUCTION_ORDER_LINE_SQL` and the section runs `ensureProductionOrderSourceLine` first. A sweep of `src/` for `line_no = po.line_no` / `lineNo = po.lineNo` finds no other copy on main.

**Impact.** UNMEASURED by this branch. Orders that BUG-498's backfill moved (1,451 on prod) are the ones whose daily figure changes. Staging's `productionRevenueByDay` (`src/api/lib/production-revenue.ts`, staging only) has the same join and needs the same fix when staging syncs.

**Regression.** `tests/production-order-line.test.mjs` now lists `dashboard-prototype.ts` and accepts the snake_case spelling, so a snake_case copy cannot hide again.
