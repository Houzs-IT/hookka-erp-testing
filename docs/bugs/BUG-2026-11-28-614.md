## BUG-2026-11-28-614 — "Set as cover" photo had no permission check `files` `rbac` 🟡

> **Last verified: 2026-11-28**

- **Found by:** read-only audit of 2026-11-28 (finding K4). `PATCH /api/files/:id/cover` (`src/api/routes/files.ts`, used by "Set as cover" in `src/pages/products/catalog.tsx`) had no `requirePermission` / `flowGate`, so any signed-in user could change the cover photo of any product or document in the organisation. Every other file write in the router is gated.
- **Fix:** the route reads the file, then applies the upload gate before any write (including the `sort_order` self-apply): a flow document's file needs that document's `update` permission (`flowGate`), anything else `files:create`. The catalog already shows the server's refusal.
- **Regression test:** `tests/files-cover-permission.test.mjs` (no role → 401 and nothing written; SUPER_ADMIN still sets the cover; the gate sits before the write).
