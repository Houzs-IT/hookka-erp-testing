## BUG-2026-11-23-547 — phone Scan Sales Order stays on "Reading the document…" for a split PDF `sales-orders` `scan-po` 🟡
- **Symptom:** on the phone (Home → Scan to Create → Sales Order), a customer-PO PDF that the queue auto-splits never leaves "Reading the document…". Found while fixing BUG-2026-11-23-543; no user report yet.
- **Cause:** the queue worker sends every PDF of 3+ pages through the document-boundary detector (`src/api/routes/scan-queue.ts`, auto-split branch). If it finds more than one document, it adds one child row per document to the same batch and marks the uploaded row `split`. The phone sheet (`ScanSoSheet.tsx` poll) watched only the uploaded row and handled `done`, `cached` and `failed`, so `split` kept it waiting for ever. The desktop modal already shows the children.
- **Fix:** `posOfSplit` in `src/pages/m/lib/scan-so.ts` waits until every child row has finished, then returns their POs, each tagged with its own row id and sample id. The sheet uses it when the row turns `split`. Each Sales Order is consumed and its accuracy sample confirmed against the child row it came from. The pick list says how many parts could not be read.
- **Regression test:** `tests/scan-so-split-pdf.test.mjs`.
