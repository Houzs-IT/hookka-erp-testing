## BUG-2026-11-24-549 — Production returned 500 on every signed-in request: Hyperdrive host no longer recognised `infrastructure` `db` 🔴

- **Symptom:** from about 05:40 MYT on 2026-11-24, every signed-in API call on erp.hookka.com returned 500, and every scheduled job that touches the database failed. `/api/health` stayed 200. `/api/pg-ping` failed after exactly 10 s. Staging, on the same code, kept working.
- **Cause:** the production Hyperdrive binding now hands the Worker a connection string whose host is `<id>.workers.alt` instead of `<id>.hyperdrive.local`. `getSql` (`src/api/lib/db-pg.ts`) chose its Hyperdrive settings only when the URL matched `hyperdrive.local`, so it fell through to the direct-connection settings: `ssl: 'verify-full'` and `connect_timeout: 10`. The driver tried to negotiate TLS with Hyperdrive's local socket, which does not do that, and timed out. Live log: `write CONNECT_TIMEOUT <id>.workers.alt:5432`. The Supabase database itself was healthy throughout.
- **Fix:** `isHyperdriveUrl` recognises both host shapes; `getSql` uses it.
- **Not the cause:** the direct Supabase host had lost its IPv4 address. The prod Hyperdrive origin was moved to the session pooler during the incident, which on its own did not bring the site back.
- **Regression test:** `tests/db-pg-hyperdrive-detect.test.mjs`.
