## BUG-2026-11-25-556 — Production Tracking: Fab Cut "Stock" column always showed "—" `production` `mrp` 🟡

> **Last verified: 2026-11-25**

- **Symptom:** on Production › Fab Cut every row's Stock cell was "—" (owner 2026-11-25 「stocks全部是-？」), although the MRP had 1,112 Ready / Waiting PO / Short statuses.
- **Cause:** `/api/mrp/stock-status` keys each status by `poId|<BOM WIP key>` (e.g. `…::0::DIVAN::…`). A Fab Cut row is one merged cut per order + fabric and carries its own wipKey `<poId>::<model>::<fabric>::FAB_CUT`, which never equals a BOM WIP key, and there is no `poId|` fallback, so the lookup always missed.
- **Fix:** the endpoint also emits `poId|@<dept>` (worst status across that order's WIPs for materials consumed in that dept; KV key bumped to `v2`). A row whose wipKey ends in `::FAB_CUT` reads `poId|@FAB_CUT`. Other departments are unchanged.
- **Known limit:** a sofa Fab Cut card merged across a set reads its anchor order only (same fabric across the set).
- **Regression test:** `tests/mrp-plan.test.mjs` (Stock column test).
