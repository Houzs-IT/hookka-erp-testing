## BUG-2026-11-11-497 — Job cards still show 0 production minutes after their BOM / WIP Times minutes were filled `production` `bom` 🟡

🟡 **On branch** (`fix/bom-minutes-fill-zero-cards` → `main`), committed, not pushed, no PR (owner 2026-11-11). Second time for this class: BUG-2026-10-05-256 ran a one-off fill and left the cause open ("a BOM edit still does not reach existing cards").

**Report (owner, screenshot 2026-11-11).** Production sheets show Prod Time 0 while WIP Times has minutes for the same step: Fab Sew BC05 = 0 min, Upholstery 5567 = 0 min (SO-2610-283 cards, shown DONE).

**Cause.** A job card copies its BOM step minutes once, when it is created (`production-builder.ts` / `jobcard-sync.ts` insert `estMinutes` into `productionTimeMinutes`). WIP Times (`PUT /api/wip-times`, `POST /api/wip-times/bulk-import`) and Edit BOM (`PUT /api/bom/templates/:id`, `POST /api/bom/templates/bulk-process-edit`) only write `bom_templates`. So a card cut while its BOM step was 0 keeps 0 forever, and every BOM filled late makes a new batch of them. Prod state for BC05 / 5567 is UNMEASURED: the browser pane was not signed in to erp.hookka.com and there are no DB credentials in this session.

**Fix.** The fill logic moved out of the route into `src/api/lib/fill-zero-minutes.ts` (`planZeroMinuteFills`, `writeZeroMinuteFills`, `bomMinutesForCard`), and the expected-card builder into `src/api/lib/expected-job-cards.ts`. All four minute-saving routes now call `fillZeroMinuteCardsForProducts` for the products they changed: that product's LIVE cards (WAITING / IN_PROGRESS / PAUSED / BLOCKED) still at 0 get today's BOM minutes, same matching rules as BUG-2026-10-05-256, audited `fill-zero-minutes-from-bom` with source `system`. Completed cards are never touched by a save (pay already ran on them); a card with minutes is never overwritten. The save response carries `zeroMinuteCards` (`{ filled, scanned }`, or `{ error }` if the fill failed; the BOM save itself still succeeds and the error is logged). The WIP Times Excel dry run fills nothing.

**Backfill of today's zeros.** Not run. Needs the deploy, then `POST /api/production/sync-jobcards-from-bom/fill-zero-minutes?dryRun=true` on prod, then the real run. Completed cards (the SO-2610-283 DONE examples) are filled only with `&completedFrom=YYYY-MM-DD`, an owner call because it changes that month's efficiency figures.

**Guard.** `tests/bom-minutes-fill-zero-cards.test.mjs` (9 cases): each of the four routes fills the live 0-minute card of the saved product and nothing else (completed card, card with minutes, other product untouched); Excel dry run and a save with no process fields fill nothing; a failed fill is reported and the save still succeeds; the product-scoped SELECT. 7 of the 9 fail with the route hooks removed. `tests/fill-zero-minutes.test.mjs` now imports `bomMinutesForCard` from the lib; `tests/bom-explosion.test.mjs` source scan points at `expected-job-cards.ts`.
