## BUG-2026-11-28-611 — PO "Mark Partially Received" changed the status with nothing received `procurement` `purchase-orders` 🟡

> **Last verified: 2026-11-28**

- **Found by:** read-only audit of 2026-11-28 (finding K1). On a CONFIRMED PO the detail page (`src/pages/procurement/detail.tsx`) and the phone (`poActions` in `src/pages/m/lib/procurement-mobile.ts`, as the secondary button) offered "Mark Partially Received" with no GRN, and `PUT /api/purchase-orders/:id` (`src/api/routes/purchase-orders.ts`) accepted CONFIRMED → PARTIAL_RECEIVED with only a permission check. The posted-GRN gate covered RECEIVED only. The GRN self-heal back to CONFIRMED (`src/api/routes/grn.ts`) runs only on GRN events, so a PO flipped by hand stayed "partly received" in the PO list filters and the AI Connector's counts.
- **Fix:** the server gives PARTIAL_RECEIVED the same gate as RECEIVED: a POSTED / CONFIRMED GRN for the PO (`GRN_OF_PO_SQL`) or `412 requiresGrn` with "Receive the goods first…". The desktop button and the phone menu item appear only once a GRN is posted (as Mark Fully Received already did); the Create GRN / Receive Goods button is how goods are received, and posting the GRN sets PARTIAL_RECEIVED by itself. How-to screen text updated (`src/api/lib/howto/screens-procurement.ts`).
- **Data — NOT changed (owner decides):** the audit's live claim ("20 of the 40 newest PARTIAL_RECEIVED POs have 0 received") was re-checked on 2026-11-28 through the AI Connector, read-only. `GET /api/purchase-orders` has no `status` filter (the handler reads only `page` / `limit`), so `?status=PARTIAL_RECEIVED` returned EVERY PO, and the 20 "zero received" rows the audit counted are CONFIRMED / CLOSED POs, not PARTIAL_RECEIVED ones. In the newest ~360 POs (down to PO-2607-0xx), 7 are PARTIAL_RECEIVED (PO-2611-054, -050, -048, -043, -040, -025, -002) and all 7 have a POSTED GRN and received quantity. Older POs were not read. The query below gives the authoritative count over the whole table:

  ```sql
  -- READ-ONLY. PARTIAL_RECEIVED POs with nothing received and no posted/confirmed GRN.
  SELECT po.id, po.po_no, po.status, po.updated_at
    FROM purchase_orders po
   WHERE po.status = 'PARTIAL_RECEIVED'
     AND COALESCE((SELECT SUM(COALESCE(i.received_qty, 0)) FROM purchase_order_items i
                    WHERE i.purchase_order_id = po.id), 0) = 0
     AND NOT EXISTS (SELECT 1 FROM grns g
                      WHERE (g.po_id = po.id OR g.id IN (SELECT gi.grn_id FROM grn_items gi WHERE gi.po_id = po.id))
                        AND g.status IN ('POSTED', 'CONFIRMED'))
   ORDER BY po.updated_at DESC;
  ```

  Any row it returns would be set back to CONFIRMED only with the owner's OK.
