## BUG-2026-11-20-538 — Packing sticker QR would not scan when a pillow shares the sticker `production` `sticker` `qr` 🟡
> **Last verified: 2026-11-20** against `src/components/qr-img.tsx` (`QRImgBase`), `src/lib/qr-utils.ts` (`qrBitmapPx`) and `tests/qr-utils.test.mjs` (branch `fix/pillow-sticker-qr-resolution`, to `main`).

🟡 **On branch** (`fix/pillow-sticker-qr-resolution` → `main`).

**Symptom.** Packers could not scan the FG packing sticker of the last sofa piece when the pillow is printed on the same sticker (example: SO-2609-361, sticker "SOFA 2/3" with "3/3 SOFA LONG PILLOW" beside it). The phone camera does not read the QR.

**Root cause.** Two things stack up. (1) When a pillow is paired, the print layout shrinks the QR from 104px to 72px (about 19mm), done in `81283ef83` to stop a tall sofa sticker clipping the QR. (2) `QRImg` passed its display size to `getQRCodeDataURL` as the bitmap width, so the 600px source that `qr-utils.ts` documents for sharp prints never applied. The `/p/<token>` link (64-character token, error level Q) is a 49×49 grid, so the 72px bitmap had about 1.4 pixels per module. Modules came out uneven, then the printer scaled the blurry bitmap up. The 104px sticker without a pillow had about 2 pixels per module and still scanned.

**Fix.** Print QRs (`QRImg eager`) now draw the bitmap at 600px (or the display size if larger) via `qrBitmapPx`. The printed size and layout are unchanged. On-screen lazy tiles keep drawing at display size so a page with 300+ tiles stays cheap.

**Regression.** `tests/qr-utils.test.mjs`: the print bitmap for a 72px QR of a real-length `/p/<token>` URL has at least 8 px per module; lazy tiles keep their display size.

**Checked.** Unit test only. Typecheck and lint skipped. UNMEASURED: a real print and phone scan of a pillow sticker on staging, and the label printer's DPI. Not fixed here: the 64-character token makes the QR a dense version 8; the printed QR is still 19mm.
