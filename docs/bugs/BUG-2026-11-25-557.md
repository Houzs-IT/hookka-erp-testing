## BUG-2026-11-25-557 — Sales Order: confirm failed with "Something went wrong" on a line not in the catalog `sales` 🟠

> **Last verified: 2026-11-25**

- **Symptom:** HK-0177 (2026-11-25). SO-2611-377 could not be confirmed; the toast said only "Something went wrong on our side" (the global 500).
- **Cause:** line 3 was `5562-1B(RHF)` with an empty `productId`: the code is not in the product list and has no BOM. The confirm BOM guard (`findIncompleteBomProducts`) skipped every line without a `productId`, so the line passed all clear 400/422 checks and went on to the production cascade. The exact throw site was not measured (Pages keeps no Function logs).
- **Fix:** the guard checks lines without a `productId` too. Such a line now stops confirm with the "Cannot Confirm — BOM Incomplete" modal naming the code, before anything is written. Prod scan: only 2 such lines in the latest 500 SOs, both on DRAFT orders.
- **Regression test:** `tests/so-empty-wip-flag.test.mjs` ("confirm is blocked for an empty WIP tab even when L1 has steps", UNLINKED line).
