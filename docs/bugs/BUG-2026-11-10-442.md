## BUG-2026-11-10-442 — A missing Anthropic key was retried 3 times and the hint named the wrong command `scan` `ocr` 🟡

Staging, 9 Nov 2026: every "Scan to create" (SO, GRN, PI, PV) failed with "failed after 3 attempts: ANTHROPIC_API_KEY not configured. Run `npx wrangler secret put ANTHROPIC_API_KEY` to enable scanning." The key was missing on the Pages project's Preview environment. Two code faults made it worse: the scan queue treated a config error as a transient miss and re-queued it up to `MAX_OCR_ATTEMPTS` (3) times, and the hint gave the Workers command, which sets nothing on a Pages project.

Fix: one message, `MISSING_ANTHROPIC_KEY_ERROR` in `src/api/lib/claude-fetch.ts`, naming `npx wrangler pages secret put ANTHROPIC_API_KEY --project-name hookka-erp-testing --env preview` (and `--env production`) plus "then redeploy". Used by `scan-engine.ts` and both `ocr-distill.ts` paths; it keeps the `ANTHROPIC_API_KEY not configured` prefix that `scan-po.ts` matches. `scan-queue.ts` fails a missing-key row on the first attempt, and the failure text now counts real attempts instead of always saying 3.

Regression: `tests/scan-missing-key-fail-fast.test.mjs`.
