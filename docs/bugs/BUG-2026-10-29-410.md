## BUG-2026-10-29-410: A blank Active cell in the raw-material batch import made the material INACTIVE `inventory` `import` 🟡

🟡 **On branch** (`fix/rm-import-blank-active-and-unit-change` → `main`). Found in a review of past ticket fixes (HK-0100, HK-0037, 2026-10-29).

**Symptom.** Importing a sheet whose Active column is empty set that material INACTIVE, on update and on create. A second row for the same item code overwrote the first row's typed values with its own blanks.

**Cause.** `batch-import-dialog.tsx` turned a blank boolean cell into `false`; the server merge (`mergeRmBulkUpdate`) and `statusFromBody` read `false` as a typed "inactive". The bulk loop also never refreshed `idToStored` after an UPDATE, so a later row for the same code merged against the original stored values. Active is the only boolean import column, so no other importer is affected. The unit-change lock (HK-0037) already ran on edit and import, but its open-PO count was not scoped by org.

**Fix.** A blank boolean is now absent (`undefined`): update keeps the stored status, create gets the default ACTIVE. After each UPDATE the bulk loop stores the merged row back into `idToStored`. `checkRawMaterialUomLocked` now counts open PO lines only within the caller's org.

**Checked.** `tests/rm-bulk-import-blank-keeps.test.mjs`, `tests/rm-uom-options.test.mjs` pass; tsc clean.

**Regression.** `tests/rm-bulk-import-blank-keeps.test.mjs`, `tests/rm-uom-options.test.mjs`.
