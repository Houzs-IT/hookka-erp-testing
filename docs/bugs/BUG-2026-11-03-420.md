## BUG-2026-11-03-420 — On-time delivery KPI: late points stopped at 0 instead of going negative `kpi` 🟡

🟡 **Fixed on branch** (`fix/hk0129-late-negative`, to `main`). Ticket HK-0129 (Violet).

**Symptom.** The KPI card for 2026-10 read "Late: 86 of 373 orders = 23.1% late → 0 points (100 − 23.1 × 5 = -15.5, never below 0)". Violet wants late orders past the zero point to cost negative points.

**Root cause.** Not a code fault: the rule was the owner's 2026-10-08 call. `penaltyParts` in `src/api/lib/kpi-catalog.ts` floored the late part with `Math.max(0, 100 - actual * per)` before the early bonus and urgent points were added.

**Fix.** The late part has no floor, so 23.1% late at 5 per 1% scores -15.5 and the bonuses are added to that. Only the late line goes negative: the KPI's total (late + early + urgent) stays between 0 and 100, so a bad month scores 0 on this KPI, never less (Violet confirmed 2026-11-03). The card's formula, late-points table ("20% → 0 · worse goes below 0, e.g. 30% → -50"), the "Your result" line and the Library rules editor say so. The breakdown says "(never below 0)" when the parts add up below 0.

**Regression.** `tests/kpi-module.test.mjs` (late, early and urgent cases updated to the negative late part).
