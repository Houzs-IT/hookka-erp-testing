## BUG-2026-11-10-444 — CN list pager always read "Page 1 / 1": older consignment notes unreachable except by search `consignment` `ui` 🟡

The Consignment Notes list loads one 200-CN server page (`/api/consignment-notes?page=&limit=200`), but its pager computed the total from the rows it had loaded (`totalCNs = cnList.length`, at most 200). So the footer said "200 consignment notes · Page 1 / 1" and Next never enabled: once there were more than 200 CNs, the older ones could not be browsed at all, only found through the search box. The route already returns the real `total`. Found by code reading while doing the G3 follow-up for the CN list (review 2026-11-10). Not reproduced in a browser; how many CNs prod holds is UNMEASURED, so whether anyone could hit this today is unknown.

Fix: `totalCNs = cnRaw?.total ?? cnList.length` (`src/pages/consignment/note.tsx`). While a header sort, funnel or grouping has widened the fetch to every CN (G3), the pager shows a single page.

Regression: `tests/docs-grid-leftovers.test.mjs` (G3 CN block).
