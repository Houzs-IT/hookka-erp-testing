## BUG-2026-11-13-509 — Floor Live doubled shared pieces; the daily efficiency report disagreed with Floor Live `floor-live` `efficiency` 🟡

🟡 **On branch** (`fix/floor-live-accuracy` → `main`).

**Symptom.** Owner, 13 Nov 2026, asked whether Floor Live is accurate (efficiency, Done, In). Checked 12 Nov against the daily efficiency report and the source rows:
1. **Done** — a piece or card with two PICs counted the FULL quantity to both people, so "Pcs done today" (770 that day) included shared work twice. Efficiency already split shared work half / half.
2. **Efficiency** — the daily efficiency report (`src/api/lib/efficiency-report.ts`) had its own older sums; 20 of 35 workers differed from Floor Live / the Employees dashboard, mostly by 0–1 %, KHIN MAUNG LIN 81 % vs 74 %.
3. **In** — shows the last department scan, not the clock-in. Owner: keep it as it is (「3remain 现在的旧可以了」).

**Fix.**
1. `piecesDoneByWorker` (`src/api/lib/floor-live.ts`) splits a shared piece / card half to each PIC (owner 「2也是解决」); the page shows .5 where it happens.
2. New `loadClosedDayPerf` (`src/api/lib/floor-live-data.ts`) runs the shared `buildPerfDays` rule for a closed day; the efficiency report takes each worker's production working minutes and earned minutes from it (owner 「1要一样」), keeping its own sums only as a fallback.

**Note.** Floor Live days already saved as snapshots keep their old piece counts (snapshots are never rewritten); from today on the split applies.

**Regression.** `tests/floor-live.test.mjs` (half split, total = real pieces; report wired to the shared rule).
