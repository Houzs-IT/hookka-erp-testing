## BUG-2026-11-27-595 — DO page "Convert to Invoice" set the status to INVOICED and created no invoice `delivery-orders` `invoices` `accounting` 🟡

> **Last verified: 2026-11-27**

- **Found by:** the screen-map pass for the AI Connector guides.
- **Symptom:** on a DELIVERED DO (normally one whose auto-invoice did not cover it: a voided invoice released it, a partial bill, or no billable SO), "Convert to Invoice" sent `PUT /api/delivery-orders/:id {status: "INVOICED"}`. The server allowed the bare flip (the code comment itself says it "does NOT create an invoice row"), so the DO read INVOICED, left every invoice-to-do list, and the customer was never billed.
- **Fix (UI):** the button opens Invoices → New Invoice with that DO picked (`/invoices?createFromDo=<id>`, `invoiceFromDoPath` in `src/lib/invoiceable-do.ts`), so the invoice is created by the one real path, POST /api/invoices. The dialog says so if the DO is not invoiceable.
- **Fix (server, both ends per PLAYBOOKS P5):** `applyDeliveryOrderUpdate` refuses DELIVERED → INVOICED with 409 unless live invoices already bill the whole DO (`bareInvoicedFlipRefusal` on `loadDoBillingState`, `src/api/lib/do-partial-invoice.ts`). A fully billed DO can still be caught up.
- **Production check:** not run by this branch (the read endpoint returns every INVOICED DO with its lines, too large to page through). SQL for a read-only count is in the PR description. No data changed.
- **Regression test:** `tests/guide-bugs-2026-11-27.test.mjs` (595).
